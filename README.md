# Прилавок: прогноз недельных продаж дарксторов

Прогноз недельных продаж для каждой пары «даркстор–отдел» сети из 45 дарксторов. Модель CatBoost обучается в Jupyter-ноутбуке, а еженедельный батч-инференс выполняет DAG в Airflow: данные берутся из PostgreSQL, модель — из S3, прогноз записывается обратно в базу.

**Стек:** Python, pandas, CatBoost, PostgreSQL, Apache Airflow, S3 (Yandex Object Storage), boto3

## Бизнес-задача

Закупки планируются вручную, отсюда дефицит в пиковые недели, списания скоропортящихся товаров и 15–20 часов ручной работы аналитиков в неделю. Нужен автоматический прогноз, который каждое воскресенье вечером обновляется, чтобы к понедельнику уйти в систему планирования закупок.

## Данные

| Таблица | Содержимое |
|---|---|
| `sales` | недельные продажи пар «даркстор–отдел», 2023-02-05 — 2025-10-26 (421 570 строк) |
| `stores` | тип и площадь дарксторов |
| `features` | внешние факторы: погода, цена топлива, CPI, безработица, промо `factor1–5` |
| `plan` | недели для прогноза, 2025-11-02 — 2026-07-26 |
| `predictions` | результат работы DAG |

Данные учебные (Яндекс Практикум) и в репозиторий не входят.

## Модель

CatBoostRegressor, 13 признаков:

- характеристики пары и даркстора: `store`, `dept`, `type`, `size`, `is_holiday`;
- история продаж пары: средняя и медиана до текущей недели, лаги 1, 2, 4 и **52 недели**, скользящие средние за 2 и 4 недели.

Ключевые решения:
- **Лаги считаются по календарной дате**, а не по позиции строки: в 605 парах есть пропущенные недели.
- **Лаг 52 недели** — продажи той же недели год назад. Он передаёт годовую сезонность и эффект конкретного праздника. Без него модель проигрывала наивному прогнозу на праздничной неделе: `is_holiday` одинаково отмечает и небольшие праздники, и ноябрьский пик.
- **Отбор признаков по PSI.** Внешние факторы исключены: у них реальный дрейф, и на период плана их нет. Календарные признаки тоже исключены, сезонность передаёт лаг 52 недели.
- **Число итераций** подобрано ранней остановкой на последних 8 неделях обучающей выборки. Валидация в подборе не участвует.

## Результаты

Валидация — последние 8 недель (2025-09-07 — 2025-10-26), в том числе одна праздничная.

| | MAE | RMSE | R² |
|---|---|---|---|
| Наивный прогноз (продажи неделю назад) | 1 591 | 3 656 | 0.972 |
| **CatBoost** | **1 293** | **2 920** | **0.982** |

- Ошибка ниже наивного прогноза на 19% по MAE и на 20% по RMSE.
- Модель выигрывает и на праздничной неделе (RMSE 5 027 против 5 278), и на обычных (2 477 против 3 362).
- Самые важные признаки: продажи неделю назад (31%), скользящее среднее за 4 недели (12%), продажи год назад (11%).

## DAG `sales_prediction_batch_inference`

Расписание: каждое воскресенье в 20:00.

```
load_data ──► preprocess_features ──┐
                                    ├──► run_inference ──► save_predictions
load_model ─────────────────────────┘
```

1. `load_data` собирает историю продаж и план во временную таблицу, присоединяет `stores` и `features`.
2. `preprocess_features` считает признаки функцией `preprocess_data` из `dags/preprocessing.py`. Это та же логика, что при обучении.
3. `load_model` загружает модель из S3 и проверяет, что её признаки совпадают с ожидаемыми.
4. `run_inference` делает прогноз, отрицательные значения заменяет на 0.
5. `save_predictions` пересоздаёт таблицу `predictions`.

**Настройка Airflow:**
- Variables: `s3_bucket_name`, `s3_model_key`, `s3_access_key`, `s3_secret_key`;
- Connection: `postgres_sales_db` (Postgres).

### Ограничение прогноза

DAG прогнозирует сразу весь горизонт плана (39 недель). Лаги 1–4 недели и скользящие средние известны только для первых недель плана, дальше они заполняются нулями — это учебное упрощение. Лаг 52 недели известен из истории для 98% строк плана.

В рабочем режиме прогноз строится на одну неделю вперёд, тогда все лаги фактические. Для длинного горизонта корректная альтернатива — рекурсивный прогноз: предсказание каждой недели подставляется в признаки следующей.

## Структура

```
.
├── model_training.ipynb        # EDA, признаки, PSI, обучение и оценка модели
├── dags/
│   ├── batch_inference_dag.py  # DAG батч-инференса
│   └── preprocessing.py        # признаки — общие для обучения и инференса
├── data/                       # сюда положить CSV (не в репозитории)
├── .env.example                # шаблон параметров БД и S3
├── requirements.txt
└── README.md
```

## Запуск ноутбука

```bash
pip install -r requirements.txt
jupyter notebook model_training.ipynb
```

Есть два варианта, откуда взять данные:
- положить `sales.csv`, `stores.csv` и `features.csv` в папку `data/`;
- заполнить `.env` по образцу `.env.example`, тогда данные загрузятся из PostgreSQL.

Выгрузка модели в S3 выполняется, только если в `.env` заданы ключи.
